# SoCcentric STM32

The website of SoCcentric STM32 (https://soccentric-stm32.github.io/). We provide firmware development consulting—working with your existing project or helping you create a new one. We use twelve open-source building blocks (A/B bootloader and its flasher GUI, C/C++ and Rust applications, hardware validation firmware and GUI, a factory provisioning station and the factory firmware) to save redundant development time and cost, and we improve these building blocks after each completed project. We also help companies port existing C/C++ projects to Rust or start new Rust projects across three popular frameworks: Embassy, FreeRTOS and Zephyr.

## Features

- One-page site with full-height slides and scroll snapping
- Hero showcase with a capture of all twelve building blocks: pick one from
  the reel, or use the arrow keys
- One slide per project with what is in the repository (build environment,
  architecture, design, implementation, tests and app features)
- Screen captures of the four desktop tools and terminal captures of the
  firmware logs on every slide
- Light and dark theme
- Header menu with dropdowns and deep links to each project
- No framework: HTML, CSS and one small script; `make check` validates links,
  captures and metadata
- Self-hosted fonts, no third-party requests and no cookies
- Works without JavaScript
- Social preview image, sitemap and structured metadata
- Branded 404 page

## Build and run

```bash
make check                    # validate links, captures and page metadata
make serve                    # then open http://localhost:8000/
```

`make check` is the repository's build target; it needs only Python 3. Pushing
to `main` deploys the site with GitHub Pages.

## Screen captures

The pictures in `assets/shots/` are real captures, not mock-ups:

- `bootloader-gui`, `validation-gui` and `factory-station` were taken from the
  running applications on their built-in simulators (BOOT Flasher without a
  board attached).
- `factory-data-gui` and the `term-*.webp` files are regenerated by
  `make shots` (`ci/capture_screens.py`). It runs the Factory Data GUI under
  Xvfb and renders the terminal blocks in `index.html` with Chromium at 2x, so
  the pictures and the page cannot drift apart.
- Requires Pillow, a Chromium binary, Xvfb, PySide6 and the sibling
  `factory-data-gui` checkout. The terminal content stays illustrative until a
  bench session is captured; the tag in the window bar says so.

- `assets/video/bootloader/` keeps the board recordings: for BOOT and each of
  the six apps a `<name>.webm` (BOOT Flasher), `term-<name>.webm` (the UART log
  read live from USART6), `<name>.log` (the same log as text) and two `.webp`
  posters. `python3 ci/record_session.py all` makes them. It **flashes the
  connected board** (BOOT over SWD, then each app through BOOT), so it is not
  part of `make`. It needs Xvfb, ffmpeg with libvpx-vp9, openocd, PySide6,
  pyserial, a NUCLEO-F767ZI on its ST-LINK port and a USB serial adapter on
  PG14. The current page does not link these recordings.

The slides themselves keep the terminals as live HTML, so text stays crisp
and theme-aware; the captures are used in the hero showcase.
