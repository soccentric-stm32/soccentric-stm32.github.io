01Bootloader

A/B bootloader, updates that can't brick

I have built bootloaders with A/B firmware upload for STM32 products. A new image goes into the inactive slot, is verified, gets a trial boot, and is kept only when the application confirms it is healthy.

B.01 · Bare metal · CSkeleton

What it does

  • Two slots, one per flash bank, so the running image is never overwritten
  • Image header with version and size, checked with CRC32 before activation
  • Trial boot with a boot counter and automatic rollback to the last good image
  • Firmware upload over UART using the HWLINK host protocol
  • Small: 32 KB, no RTOS, no dynamic memory

Adapted to your flash map and your update path: UART, USB, CAN or Ethernet.

soccentric-stm32-bootloader on GitHub

02Application · C/C++

Applications in C/C++

The language most STM32 products ship in. I have built applications bare metal on HAL/LL and on top of an RTOS, with the bootloader contract built in from day one.

A.01 · C/C++ · FreeRTOSSkeleton

What you get

  • 216 MHz clock tree, MPU and caches, fault handlers, watchdog

  • Health check that confirms a new image to the bootloader

03Application · Rust

Applications in Rust

The same application in Rust: memory safety checked at compile time, with no runtime cost on the MCU. A good fit for new products and for teams moving off C.

A.02 · Rust · EmbassySkeleton

What you get

  • no_std on Embassy, with async tasks instead of threads
  • Same specification as the C and Zephyr versions
  • Same flash slot and bootloader contract, so one updater serves all
  • Current stable toolchain, clippy clean
  • One-command build and flash in the shared Docker image

06Validation · Firmware

Validation firmware

Firmware that tests every block of the chip and the board, so you know the hardware works before the application is written and before each board ships.

V.01 · C · FreeRTOSImplemented

What it covers

  • 201 test cases in 28 groups: CPU, memory, clocks, analog, communication and more
  • Test levels for harness, lab equipment and operator checks
  • Operator prompts for buttons, LEDs and anything a person must confirm
  • Scriptable CLI over UART, with text and JSON reports
  • Requirements written down in an SRS

08End line testing

End-of-line test and provisioning

A station tool for the factory floor: every board is flashed, tested, given its identity and locked, and the record is kept.

E.01 · HWVAL Factory · PythonSpecified

Factory automation

  • Flow engine driven by product profiles, not code changes
  • Several fixtures in parallel, simple screens for operators
  • Serial number and MAC allocation, written to the device
  • Readout and write protection set before the board leaves
  • ZPL labels and a full provisioning record for traceability
