How it fits together

The desktop app talks to whichever firmware is running over the ST-LINK virtual COM port, using the binary HWLINK protocol. It uses SWD through OpenOCD only to flash and provision the board.

Bench configuration

Single-bank flash (nDBANK = 1). HWVAL fills sectors 0–10 and keeps sector 11 free for its destructive flash tests. It is flashed over SWD.

Product configuration

Dual-bank flash (nDBANK = 0). The bootloader is in bank 1 and there is one 976 KB application slot per bank. The GUI switches between the two configurations over SWD.

A/B bootloader

An update only ever writes the inactive bank. A new image boots on trial and must confirm itself; otherwise the bootloader returns to the last good image.

  1. UploadThe GUI sends the image in 1 KB chunks; only the inactive slot is erased and written.
  2. VerifyThe header and the image CRC32 are checked against what was read back from flash.
  3. ActivateThe slot gets a higher sequence number and is marked pending, then the board resets.
  4. Trial bootThe bootloader starts the pending image with the IWDG running and counts the attempt.
  5. Confirm or roll backA healthy app writes CONFIRMED. After 3 failed boots the slot is REJECTED and the old one boots again.
DecisionChoice
Flash modeDual-bank, bank swap at run time
Update pathUART (ST-LINK VCP), HWLINK
IntegrityCRC32 using the hardware CRC unit
RollbackTrial boot, 3 attempts, IWDG backstop
Boot stateAppend-only metadata records + backup registers
RecoveryHold B1 at reset, or SWD

HWLINK protocol

One FlatBuffers schema shared by the GUI and all three firmware images. Frames are COBS-encoded, end with 0x00 and are protected by CRC32, so the receiver resynchronises after any error.

FieldSizeMeaning
proto1Protocol major version
flags1Response / event
seq2Sequence number, echoed in the reply
payloadnFlatBuffer, root Message, id HWLK
crc324CRC-32/ISO-HDLC (same as zlib.crc32)

One build environment

All firmware builds in the same Docker image: arm-none-eabi-gcc 13.2, CMake and Ninja, OpenOCD and STM32CubeF7 v1.17.4 as shipped. The host only needs Docker.

scripts/docker-dev.sh build     # build the stm32-dev image once
scripts/build.sh                # configure + build inside the container
make flash                      # program over SWD, verify, reset
make serial                     # ST-LINK VCP console, 115200 8N1
