01Bootloader · GUI

BOOT Flasher, build and flash from one window

A desktop app that builds the bootloader, programs it onto the board, then builds, signs and uploads your firmware projects.

Python · PySide6Implemented

Features

  • Build, sign and flash from one window, with no commands to type
  • Checks the board's slots, key and security counter before it writes anything
  • Warns about key and counter problems
  • Recovers a board that does not answer
  • Every step also runs on its own
  • Light and dark theme

02Bootloader · Firmware

A/B bootloader, with automatic rollback

A small bootloader with two application slots. A new image goes into the inactive slot and is kept only when the application confirms it is healthy. Otherwise the bootloader goes back to the last good image.

Bare metal · CFeature-complete · v0.1

Features

  • Two slots, one in each flash bank
  • Only signed images are accepted
  • Trial boot under a watchdog, with rollback after three failed starts
  • About 28 KB of bare-metal C: no RTOS and no dynamic memory
  • Updates over UART with bootctl.py, signing with mkimage.py
  • Tested with host tests on a simulated flash and a hardware rollback test

03RTOS · FreeRTOS

FreeRTOS application in C

The reference application and the starting point for a new product. It runs under the bootloader and confirms itself after a health check.

C · FreeRTOS · STM32CubeF7Feature-complete

Features

  • Four FreeRTOS tasks: Health, Comms, Button and LED
  • Static memory only, so nothing is allocated once the scheduler runs
  • Seven LED patterns, a debounced button and nine host commands
  • Runs from either slot
  • The build checks a 128 KB flash and 64 KB RAM limit
  • CI runs static analysis, boot-contract and image checks

04RTOS · Zephyr

Zephyr application on Zephyr 4.4

The same application on Zephyr, for products that want a full OS with drivers and networking. It uses the same slots, protocol and health check as the C FreeRTOS version.

C · Zephyr 4.4.2Implemented

Features

  • Uses devicetree, Kconfig and threads
  • Lets you compare Zephyr and FreeRTOS on the same product before you choose
  • Interrupt-driven UART, with faults saved in no-init RAM
  • Host link can switch to 921600 baud, with a fallback
  • A Kconfig option forces a rollback for testing
  • Docker build with Zephyr and its SDK pinned

app-c-zephyr on GitHub ↗

05Rust · Embassy

Rust application on Embassy

The same application in no_std Rust on the Embassy async executor. Use it to start a new Rust project or to port C/C++ firmware.

Rust · Embassy · no_stdFeature-complete

Features

  • Four async tasks and no heap
  • Same boot contract and host protocol as the C versions
  • Framing and CRC checked against the reference encoder
  • Pinned Rust toolchain and locked crates in Docker
  • CI runs build, clippy and format checks
  • Host link at 115200 or 921600 baud

app-rust-embassy on GitHub ↗

06Rust · FreeRTOS

Rust application on FreeRTOS

The same application in no_std Rust, with its tasks on the FreeRTOS kernel. A thin C layer covers GPIO, UART, watchdog and flash.

Rust · FreeRTOS · no_stdImplemented · bench test pending

Features

  • Keep the FreeRTOS kernel and drivers you trust and write the logic in Rust
  • One CMake build for the C and Rust parts
  • Rust panics, FreeRTOS asserts and stack overflows share one fault path
  • No allocator
  • CI runs build, static analysis, format and boot-contract checks

app-rust-freertos on GitHub ↗

07Rust · Zephyr

Rust application on Zephyr

The same application in no_std Rust on Zephyr 4.4, using Zephyr's own Rust support. A small C layer covers what the Rust bindings do not reach yet.

Rust · Zephyr 4.4.2 · no_stdImplemented · bench test pending

Features

  • Rust on a mainstream RTOS, with devicetree and Kconfig kept as they are
  • About 45 KB of flash and 35 KB of RAM
  • Four threads, with the same watchdog and trial contract
  • The host-link codec is shared with the Embassy build
  • rustfmt and clippy with warnings as errors

app-rust-zephyr on GitHub ↗

08Validation · Firmware

HWVAL, the validation firmware

Firmware that tests the STM32F767ZI and the NUCLEO board, at bring-up and before a board ships.

C · FreeRTOS · LwIPImplemented · hardware fix in progress

Features

  • 196 tests across the hardware blocks
  • Three test levels, with operator prompts for manual steps
  • Destructive tests are kept to a reserved flash sector
  • Ethernet (LwIP), USB, SWO and watchdog checks
  • Run it from a console, a script or the GUI
  • JSON and Markdown report for each board

09Validation · GUI

HWVAL Studio, the bench app

A desktop app for macOS, Windows and Linux that runs the HWVAL tests, shows the results live and keeps a history of runs.

Python · PySide6 · SQLiteImplemented · v0.1.0

Features

  • Run tests by group and watch the results live
  • Reports in JSON, Markdown and PDF
  • Built-in device simulator, so it works without a board
  • Operator mode with prompts and an optional PIN
  • Run history in SQLite, with compare
  • Updates firmware through the bootloader and flashes over SWD
  • Headless command line for CI

10Factory · Station

HWVAL Factory, test and provisioning

The end-of-line station for the factory floor. For each board it flashes, tests, gives the board its identity, programs the product, protects flash, prints the label and records the result.

Python · PySide6 · OpenOCDIn development · v0.1.0

Features

  • One operator action per board
  • A full simulator runs every step without hardware
  • Designed for up to eight fixtures on one PC; the hardware side is still in development
  • Product profiles, PIN login by role and work orders
  • A SQLite record for every unit
  • Bench pages for a blank board: detect, flash, device info, calibration, diagnostics

factory-station on GitHub ↗

11Factory · Firmware

Factory firmware, the first app on a new board

A small FreeRTOS app that the factory station flashes into slot A. It stores each unit's system info, calibration and diagnostic data when the station sends them over UART.

C · FreeRTOS · UARTIn development · v0.1.0

Features

  • Three 4 KB blocks: system info, calibration and diagnostics
  • Writes outside those blocks are refused
  • Checks headers, CRCs and the chip UID, then reads back what it wrote
  • Commands: INFO, READ, WRITE and DIAG_INIT over UART
  • Host tests run the real command handler on a simulated flash

Specification ↗factory-firmware on GitHub ↗

12Factory · Data GUI

Factory Data, CSV to unit files

A desktop app that turns CSV files into the .sys, .cal and .diag files for each unit. The factory station writes these files and the factory firmware stores them.

Python · PySide6Implemented

Features

  • One file per unit, made from a spreadsheet
  • Preview the records, then write one file or all of them
  • Sample CSV files to start from
  • An Inspect page checks CRCs and lists the items in a file
  • An optional chip UID ties a file to one chip
  • The core package has no Qt, so it is easy to script
